- store in Chroma/Pinecone

-----------------------------------------------------------------------------
5. Ready for queries

Fixed Chunking 
-> splits text by a rule that ignores meaning - usually a fixed number of characters
-> eg every 500 tokens or 50 tokens of overlap
Semantic Chunking
-> splits text based on meaning/topic boundaries instead of raw character count 
-> works by embedding sentences then measuring the similarity between consecutive sentences 
-> when similarity drops below a threshold that's a topic shift it cuts there

==============================================================================
Four Chunking Variables That affect quality 
1.Chunk size
too small --> Loses context
sweet spot --> 200- 1000 tokens
too large --> dilutes meaning
2.Overlap
chunk 1 overlaps (10-20%) with chunk 2
3.Split Bonudaries 
Fixed -->  random cut
Recursive --> cutting at Paragraph/sentences
Semantic --> cutting at meaning boundaries (with cyan glow - best)
4. Content Type
Code 
Legal 
Markdown
Each needs different treatment

Recursive Chunking

Semantic Chunking -> Best Quality
-> splits at meaning boundaries , not arbitary points 
-> oauth topic chunk 1:[40,50,60] --- rate limit topic chunk 2:[54,55,56]
-> used when accuracy matters more than speed
how it works:
1.Embed each sentence
2.compare adjacent embeddings
3.split when similarity drops

Three Rules For production RAG:
1. Same Embedding model Everywhere 
Ensure consistency across ingestion, indexing and query. 
Avoid mismatch error
------------------------------------------------------------------------------------
2. Embed Quality > Quantity 
Prioritize high-quality relevant vector over massive noisy dataset
Less is often more
------------------------------------------------------------------------------------
3.Test Retrieval Seperately
Validate Retrieval performance independent of generation 
use specific evaluation metrics
